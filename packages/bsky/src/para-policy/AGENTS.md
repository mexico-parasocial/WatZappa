# Signed policy publication

- The standalone publisher signs governance-authorized material only. Never connect raw membership index rows or client-submitted roles directly to it. The reviewed boundary is `materializeGovernanceMembers`: transaction-bound, board-bound, admission-only, deterministic; roles stay out until a board-issued authority trace is persisted. An active membership needs a matching indexed `com.para.community.admission` issued by the board repository. Removed/blocked board decisions override self-authored active membership.
- Keep publisher encoding independent of PDS implementation imports; exercise both implementations in interoperability tests when changing normalization, claims or digest ordering.
- Construct `ParaPolicyOutbox` with `db.$pickTables<'para_policy_publication' | 'para_policy_outbox'>()`. Call `enqueue` inside the authorized governance transaction, retaining the stable event ID. AppView's INT8 number parser is required.
- The stream row lock serializes version/epoch allocation and leasing. Never regenerate an envelope for a retry or rotate keys by re-signing old versions. Only acknowledge an authenticated receiver's exact version/digest using the current lease token.
- Expired head delivery latches `recovery-required`; never skip it or manually clear the latch. Keep acknowledged envelopes/event IDs until a reviewed retention/recovery protocol permits pruning.
- `reconcileAccepted` requires an authenticated exact receiver receipt and may only repair delivery bookkeeping. It cannot clear PDS stale state or bypass a later expired head; never feed it unauthenticated response JSON.
- Checkpoint recovery reserves version and epoch independently, each above the publisher head and the receiver challenge's verified floor, inside the governance transaction. While a checkpoint is pending, enqueue and ordinary claim stay blocked; release the latch only through `acknowledgeCheckpoint`/`reconcileCheckpoint` with an exact authenticated receipt. Superseded events are retained with `supersededAt` and never redelivered; a new checkpoint may only be signed above an expired one, never by re-signing old versions.
- The authenticated transport client refuses any response not signed by the pinned PDS key, addressed to this issuer, and bound to the request jti; the coordinator acknowledges only on that authenticated exact receipt. Never feed a transport response into acknowledge/reconcile without `ParaPolicyTransportClient` verification.
- The indexer has an optional `ParaPolicyPublicationService` injection, off by default. Publication and materialization must share the same database transaction; never feed user-supplied policy material into this service. Do not enable the injection or the PDS transport router without a reviewed delivery worker, checkpoint resume, trust/key custody, and end-to-end regression. Public JWKS output must never contain private key material.

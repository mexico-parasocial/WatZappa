## Goal

Clean up the orphaned PARA surface (starting with `getSentiment`), add a durable guard against future orphan handlers/lexicons, and answer the structure question. No folder restructuring — the audit showed the current layout already matches upstream exactly.

## Best-practice verdict on folder structure (no changes needed)

Upstream `bluesky-social/atproto` organizes **one file per XRPC method** under namespace folders, with bsky's `api/index.ts` importing each handler individually (no namespace index files in bsky) and pds using per-namespace `index.ts` modules. Both PARA trees already follow exactly this: bsky imports ~51 handlers individually, pds uses namespace `index.ts` modules under `api/com/para/`. **Keep the structure.** The genuine best-practice gaps are elsewhere: no lexicon↔handler parity enforcement (which is how orphans like `getSentiment` appeared), the `@ts-nocheck` exemption covering nearly the whole PARA surface, and undocumented no-caller endpoints.

## Changes

**1. Remove `com.para.discourse.getSentiment`**
- Delete `packages/bsky/src/api/com/para/discourse/getSentiment.ts` (56 lines, zero importers, no lexicon JSON — it was never registrable).
- Keep the dataplane support (`GetParaDiscourseSentiment` proto rpc, `data-plane/server/routes/discourse.ts`) — the backing capability stays for when the endpoint is properly specced.

**2. Remove the unbuildable `getDeliberationClusters` test calls**
- In `packages/bsky/tests/qvl-queries.test.ts` (~lines 323, 390): remove the two invocations and their assertions. The method has no lexicon, handler, proto, or dataplane route, so the test cannot pass as written.

**3. New parity guard: `packages/bsky/tests/para-lexicon-parity.test.ts`**
- Walks `lexicons/com/para/**` for method-type lexicons (query/procedure/subscription) and asserts each NSID is either registered on the bsky XRPC server or listed in a new checked-in `packages/bsky/src/api/com/para/lexicon-exceptions.json` (entries tagged `planned-civicTree` / `planned-discourse`, covering the 9 civicTree methods + `getAnalysis`).
- Reverse direction: every registered `com.para.*` method must have a loaded lexicon (catches `getSentiment`-style ghosts permanently).
- Follow the repo's `testing` skill for runner/placement conventions when implementing.

**4. Surface inventory doc: `packages/bsky/src/api/com/para/README.md`**
- Table of all `com.para.*` methods (bsky + pds) × caller evidence: in-repo callers (tests, dev-env seed `para-demo.ts`, matrix-bridge `backfill.ts`) vs assumed-external (frontend). This is the "is it used by the ecosystem" answer, kept honest in-tree.

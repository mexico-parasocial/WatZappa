## Goal

Finish the two open threads in the matrix-bridge: complete the F9 authorization migration across every remaining endpoint (the audit found 18 community-scoped reads with cross-community enumeration, 9 other-user-DID reads with no privacy check, one write with zero ownership binding), and wire the three reserved SSE producers (`chat.unread`, `badge.updated`, `constitution.updated`). No schema changes. Institutional room ownership/transfer stays out — it needs its own design round.

## Part 1 — Complete F9 (src/authz.ts + routes)

**1. New helper in authz.ts** — `authorizeUserRead(ctx, actor, targetDid, communityUri)`: allowed iff `actor === targetDid` OR the caller holds moderator/owner in that community (reuses `decideCommunity(..., 'community.moderate')`). Unit-tested like the rest of the policy.

**2. Route migrations** (each: authenticateM8 stays, add the authorize call, keep self-eq checks that remain meaningful):

- `governance-read.ts`: constitution / proposals / decisions → `community.read` on the `uri`/`community` param.
- `moderation.ts`:
  - `chat-member-list`, `chat-badges` → `community.read`; chat-badges additionally `authorizeUserRead` on the `did` param.
  - `user-chat-preferences` GET → self-only (per decision): 403 unless `did === auth.did`.
  - `moderation-report` → replace manual participation-stats check with `community.contribute` (reporter side).
  - `moderation-sanction`, `moderation-recompute` → replace manual `is_moderator` stats checks with `community.moderate`.
  - `moderation-dashboard` → drop the now-redundant stats check (authz already covers it).
- `sortition.ts`:
  - `POST /runs` → `sortition.run` (action exists, never called).
  - `GET /runs` → `community.read` on the run's community (resolves via `cabildeo`'s community; gating the selected-members listing per decision).
  - Proofs stay public per decision: `sortition-proofs`, `sortition-proof`, `verify-sortition`, `proof-as-record` keep M8-only — documented as deliberate public-audit surface.
- `deliberation.ts`:
  - Reads: `cards` GET, `community-tree/contributions` GET, `graph`, `suggestions` GET, `summarize`, `community-pulse`, `votes` → `community.read`; the `viewer`/`voter` query params additionally `authorizeUserRead`.
  - Writes: `cards` POST, `contributions` POST, `contributions/vote` (resolve the contribution's community first), `relationships`, `suggestions/accept`, `extract` → `community.contribute` (self-eq on author/voter DID stays).
  - `suggestions/reject` → the one unbound write: load the suggestion, enforce self-eq on its author + `community.contribute`.

**3. Error semantics**: unknown resources keep current 404s; authorization failures return 403 via AuthzError — matches the contract doc.

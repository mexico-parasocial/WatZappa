## Architecture verdict

The two-provider direction is sound (validated by solidarity's own BYOMA design) and the backend leg is built. The review found three things to correct — one latent bug, one wrong-direction integration, one dead liability — plus the client reality that changes the chat redesign from "greenfield" to "wire up what's already there":

1. **Latent bug — the appservice registration promises a push endpoint nothing serves.** `para-bridge-registration.yaml` declares `url: http://para-matrix-bridge:3001`, so Synapse will POST `/_matrix/app/unstable/transactions/{txnId}` to the bridge — and the router has no such route. Every event in a namespace room triggers a 404 + Synapse retry storm.
2. **Wrong direction — we push-registered but still poll.** The 30s `MatrixSyncPoller` hits the Synapse admin API per room, with in-memory-only cursor state. Serving transactions instead turns ingestion push-based, drops the admin dependency for messages, makes `chat.unread` near-real-time, and fixes (1). Poller stays as a slow reconciliation fallback.
3. **Dead liability — `user_matrix_map.password`.** Write-once, never read (`getUserPassword` has zero callers; sessions come from appservice/admin login). Generating and persisting unused passwords is pure risk. Stop storing them.
4. **Client accelerator — the PARA app already has the native engine.** `@unomed/react-native-matrix-sdk` (Rust, E2EE, sliding sync, SecureStore secrets) is a production dependency with a working lab client (`src/features/encryptedChat/client.native.ts`) and **no UI consumers**. The redesign wires this in; the WebView shell becomes fallback. Also found: native bottom-bar chat badge ignores Matrix unread (only DM unread) — fix in redesign.

## Next stage — this repo (services/matrix-bridge + lexicons)

**1. Appservice transactions endpoint** (correctness + real-time):
- Route `POST|PUT /_matrix/app/unstable/transactions/:txnId` authed by `hs_token` (from `MATRIX_APPSERVICE_TOKEN`'s registration sibling — new `MATRIX_HS_TOKEN` env).
- Dedup: persist `last N` txnIds in sqlite/pg (`as_transactions` table); ack 200 only after ingest.
- Feed accepted events through the existing pipeline: `insertMatrixEvent` (idempotent), `recordMessage` for participation, aggregate `chat.unread` publish (reuse producer; coalesce per transaction per room).
- Demote `MatrixSyncPoller` to fallback: interval 30s → 300s default, config-overridable (`BRIDGE_SYNC_FALLBACK_MS`); add metrics (`as_transactions_total`, ingest lag).
- Tests: hs_token auth (401 wrong token), txn dedup (second POST same id = 200 no-op), message ingest fires chat.unread.

**2. `com.para.identity.linkedChat` lexicon + verifier**:
- Record lexicon `lexicons/com/para/identity/linkedChat.json`: `{ provider, matrixUserId, linkedAt }` in the user's PARA repo; the reciprocal record (in the linked account's repo) carries the PARA DID. `pnpm codegen`; bsky lexicon-parity test covers records automatically.

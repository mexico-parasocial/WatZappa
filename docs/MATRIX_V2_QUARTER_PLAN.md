## Deployment and migration

First establish whether the target is a fresh deployment or an existing v1
system. The old plan's "stage 1 already running for two months" is not a fact.
For a legacy system, rehearse against its real backup and record the witnessed
destruction of mappings, old tokens and password material using MATRIX_V2's
procedure. For a fresh deployment, document which legacy gates do not apply.
Prepare rollback before onboarding; do not assume a production v1 fallback
exists, or downgrade encrypted content as a recovery strategy.
